# 自動撮影スクリプト修正計画

対象: v2.0.0 / versionCode 31。目標は3端末×4言語×7画面＋Desktop×4言語×6画面＝108枚。実装・撮影は未実施。

## 1. 撮影条件の共通定義

新規 `scripts/store_capture_config.json` に対象版、言語、PDF、ページ数、目次項目、端末プロファイル、撮影順・掲載順をまとめる。

- スマホ・タブレット: 既存6scene＋07_outline。掲載順は02、01、04、07、03、05、06。
- Chromebook_FHD: 02、04、07、03、05、06。全scene横。01_readerは対象外。
- プロファイルには画面解像度・密度・回転方式・最大化の要否・sceneごとの期待レイアウトを持たせる。
- Tablet_7は1080×1920・360dpi。他端末は既存解像度。
- PDFの8ページ条件は維持する。既存4言語PDFに8項目の目次があることは確認済み。
- JSONをホストと検品が読む。Androidテストには必要な値をinstrumentation引数で渡し、端末判定やscene一覧を重複定義しない。

## 2. scripts/capture_store_screenshots.py

- 共通定義からCLI選択肢と撮影一覧を作る。--scene未指定なら各端末の対応sceneを使用。明示指定に未対応の組合せがあれば端末操作前にエラーにする。
- 全PDFの存在、AVD・システムイメージ、設定の整合性を撮影前に確認する。
- 起動後にwm size/densityの物理値・overrideと回転設定を記録する。Tablet_7のみ一時変更し、各言語の完全再起動後も有効値を再確認する。
- finallyで既存overrideを正確に復元する。元が未設定ならreset、元が設定済みならその値に戻す。復元失敗は明示し、成功扱いしない。既存起動端末は終了しない。
- Desktopは物理回転とrequestedOrientation強制を使わない。ライトテーマ、横画面、アプリ最大化を別処理で整える。
- 最大化操作はDesktop日本語で先に実証する。UI Automatorでcaption操作を探索し、見つからなければ権限と対応APIを確認したウィンドウ制御を検討する。座標だけで成功と判断せず、実際のアプリ領域とwindowing modeを検証する。
- 言語変更は既存root＋LocaleSetterを使い、Desktop API 34で先行検証する。失敗時は別言語表示で代用しない。
- 回転方式、目次項目、期待レイアウト等をテストへ渡す。PNG寸法、比率、RGB／透過なし、最低解像度を厳密に検査する。
- JSON記録に設定schema版、アプリ版、実解像度・密度、Activity領域、Desktop最大化結果、目次確認結果を追加する。
- fingerprintに共通設定も含める。今回の設定・UI変更は既存互換fingerprintを使って再利用しない。
- 失敗した端末・言語・sceneと未撮影一覧を記録し、非ゼロ終了する。完成画像だけ再開可能にする。

## 3. StoreScreenshotTest.kt

対象: app/src/androidTest/java/com/github/tyamada/mihirakipdfviewer_android/StoreScreenshotTest.kt

- 03・06: btn_settingsクリック後、プルダウンの「設定」を選び、設定画面の表示を待つ。
- 07_outline: outline取得と期待項目を確認し、目次を開く。項目選択によるページ移動を検証し、再度目次を開いて撮影する。見開きでは移動先が左右いずれかに含まれることを判定する。
- Desktop: テスト開始時と再起動のたびに最大化し、物理ディスプレイ寸法とActivity領域を別々に検査する。既存の縦横固定assertをプロファイル依存に変更する。
- Desktopの06はマウス操作設定を見せる。必要なsceneでmouseNavigationを有効化する。マウスの入力sourceを指定した左右端クリックと矢印キーの移動を先行検証し、安定したページに戻して撮影する。
- 目次の表示項目、選択先、移動結果、実際のウィンドウ状態を記録する。検索・描画・前面アプリの既存検査を維持する。

補助変更: ViewerScreen.ktの目次ボタン・ダイアログ・設定メニュー項目に安定したtestTagを付ける。目次見出しとcontentDescriptionを文字列リソースへ移し、対象4言語を用意する。製品画面への撮影専用ボタンは追加しない。

## 4. scripts/review_store_screenshots.py

- 共通定義から端末別の期待画像集合を作り、84＋24＝108枚を検査する。部分撮影の確認にはdevice/language選択を追加し、レポートへ選択範囲と全体未完了を明記する。
- versionCode 29、72枚、6枠、固定の報告文を廃止し、対象版とscene数から生成する。
- 7枚は3列×3段、6枚は3列×2段など、一覧の高さを動的計算する。掲載順を共通定義から使う。
- 目次項目・ジャンプ検証結果、Desktop最大化、解像度・向き・言語・版・ハッシュ・重複を確認する。
- fingerprint計算を撮影側と共有し、旧版画像を合格にしない。目視完了は選択範囲の全画像を確認した場合だけ記録する。

## 5. scripts/test_capture_store_screenshots.py

既存のPDF欠落・resume・画像検査を維持し、以下の失敗防止を追加する。

- 端末別scene選択と未対応組合せの拒否。
- 解像度overrideの未設定／設定済み双方の復元。撮影失敗・再起動・中断時の復元と対象外端末を操作しないこと。
- 共通設定変更・版違い・解像度違いの画像をresumeで拒否。
- 目次検証失敗・Desktop最大化失敗を完成画像として保存しないこと。
- 検品の欠落検出、7枚目が欠けない一覧生成、部分撮影を全体完成と報告しないこと。

ホスト側のモック試験ではDesktop実挙動やLocaleSetter互換性は保証しない。これらは実AVDで確認する。

## 6. 実装・確認の順番

1. 共通定義、設定メニュー対応、目次scene、ホスト検査を実装する。
2. ホスト試験とアプリ・テストAPKのビルドを実行する。
3. Smartphone_6.3・日本語で目次、設定2scene、既存読書・検索sceneを確認する。
4. Tablet_7の変更・復元を正常時／失敗時に確認し、両タブレット日本語各7枚を試す。
5. Chromebook_FHD・日本語で起動、転送、最大化、入力、6sceneを試す。英語切替と完全再起動も試す。
6. 修正が必要ならここまでに反映し、全4言語へ展開する。必要な範囲だけ再試験する。
7. 108枚の自動検品と目視確認を行い、手順書・撮影結果を更新する。

StoreLocaleSetterはAPI 34で動作確認してから、必要な場合だけ互換対応する。旧capture_screenshots.py群は修正せず、正規入口をscripts/capture_store_screenshots.pyへ統一する。

## 完了条件と限界

108枚が対象版・言語・解像度・構図条件を満たし、旧画像との混同がなく、端末設定復元と再開が成功すること。ウィンドウ最大化や言語切替が安定しないDesktop条件は未完了として報告し、無理に合格扱いにしない。

Desktop AVDはChromebook向け検証手段として使用する。ChromeOS固有のUI・挙動を再現したと表示しない。Play Console登録は別工程。
